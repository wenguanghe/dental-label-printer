# 📄 最终版 PRD：口腔门诊器械消毒标签打印系统

## 一、 文档概述
### 1.1 项目背景与目标
口腔门诊对医疗器械的消毒感控有严格的合规要求（如《口腔器械消毒灭菌技术操作规范》WS 506-2016）。消毒后的器械必须贴有包含详细追溯信息的标签。
本项目旨在开发一套**移动端优先、无需登录、开箱即用**的Web标签打印系统，解决传统手写或旧系统效率低、易出错、难追溯的问题，全面提升消毒登记人员的工作效率与门诊合规水平。

### 1.2 运行与开发环境
*   **运行环境**：Windows 10及以上系统（宿主机）。Web服务运行在Docker容器中；本地打印Agent运行在Windows宿主机。
*   **开发环境**：macOS系统（需配套虚拟打印Mock方案进行跨平台调试）。
*   **硬件要求**：支持主流热敏/热转印标签打印机（如斑马、得力、芯烨等），支持外接蓝牙/USB扫码枪。

---

## 二、 系统架构设计（核心技术方案）
为解决“Docker容器无法直接调用宿主机本地打印机”的技术壁垒，系统采用 **“Web服务端 + 本地打印Agent”** 的双端架构：

1.  **Web服务端（运行于Docker内）**：
    *   负责前端页面渲染、业务逻辑处理、数据存储（SQLite/JSON）、统计报表生成。
    *   通过 WebSocket 与本地 Agent 保持长连接。
2.  **本地打印Agent（运行于Windows宿主机）**：
    *   一个轻量级后台服务（建议使用 Node.js + `pdf-to-printer` 或 Python + `win32print`）。
    *   开机自启，监听 WebSocket 消息。接收到打印指令后，调用 Windows 本地打印驱动将指令发送给物理打印机。
    *   **Mac开发Mock模式**：在Mac开发时，Agent接收到指令不调用真实打印机，而是生成标签的 PDF/图片 并自动弹窗预览，实现跨平台完美调试。

## 三、 用户角色与使用场景
*   **主要用户**：口腔门诊消毒供应中心（CSSD）护士/消毒登记人员。
*   **使用场景**：
    *   双手可能佩戴橡胶手套，或有水渍/消毒液残留（要求UI按钮大、容错率高）。
    *   工作节奏快，需要快速选择器械、设置时间并连续打印多张标签。
    *   遇到标签打印模糊、卡纸或贴错时，需要快速补打。

## 四、 功能需求详细说明

### 4.1 核心打印模块（移动端优先）
**UI/UX要求**：大触控区域（按钮高度≥48px），高对比度色彩，支持语音播报反馈（如“打印成功”、“打印机缺纸”）。

| 功能模块 | 字段/功能点 | 详细规则与交互说明 | 属性 |
| :--- | :--- | :--- | :--- |
| **基础信息** | **器械名称** | 下拉选择，支持拼音首字母/关键字模糊搜索。若字典无此器械，可点击“手动输入”（手动输入不写入字典）。 | **必填** |
| | **消毒人员** | 下拉选择或搜索，支持手动输入。 | **必填** |
| | **核对人员** | 下拉选择或搜索，支持手动输入。 | **必填** |
| | **炉次/炉号** | 下拉选择或手动输入。**支持记忆功能**，默认选中上一次使用的炉次/炉号。 | 选填 |
| **时间设置** | **消毒时间** | 默认当前时间。提供时间选择器，格式：`XXXX年XX月XX日 XX:XX`，精确到分钟。允许手动修改（用于补录）。 | **必填** |
| | **失效时间** | 默认当前时间+3个月。提供时间选择器。<br>💡**优化**：增加合规快捷按钮 `[7天]` `[14天]` `[180天]` `[自定义]`，一键计算失效时间。 | **必填** |
| **批量与数量** | **多器械选择** | 支持一次添加多个不同的器械到“待打印列表”。 | - |
| | **数量设置** | 每个器械旁提供数量输入框（默认1），支持“+ / -”快捷按钮。支持外接扫码枪扫码直接带出器械和数量。 | - |
| **执行打印** | **开始打印** | 点击后生成对应数量的标签，下发给Agent。显示进度条，防重复点击。 | - |
| | **追溯二维码** | 💡**优化**：标签角落自动生成二维码。扫码可在移动端展示该器械的完整消毒追溯信息。 | 默认开启 |

### 4.2 历史记录与一键补打模块（新增核心功能）
*   **痛点解决**：解决标签被水沾湿模糊、撕坏、打印机卡纸导致需要重新填写的痛点。
*   **功能描述**：
    *   展示“今日打印历史”列表，按时间倒序排列。
    *   列表显示：器械名称、数量、消毒人员、消毒时间。
    *   **一键补打**：点击任意历史记录，直接原样下发打印任务（系统可配置：补打时是保留原消毒时间，还是更新为当前补打时间）。

### 4.3 数据统计与报表模块
无需登录，通过底部导航栏进入。支持按日、周、月、自定义时间段筛选。
*   **器械消毒统计**：柱状图/列表展示各器械的消毒总次数、近期趋势。
*   **人员工作量统计**：统计每位“消毒人员”和“核对人员”的操作次数，辅助绩效考核。
*   **设备使用统计**：统计各“炉次/炉号”的使用频率，辅助判断消毒炉的损耗与维护周期。
*   **数据导出**：支持将统计报表一键导出为 Excel 格式，应对卫健委/院感检查。

### 4.4 数据字典与系统设置模块（替代原Markdown方案）
*原需求使用本地Markdown，现优化为系统内置Web管理，降低维护门槛。*
*   **字典管理**：提供Web页面，护士长可直接在手机上增、删、改“器械名称”、“人员名单”、“炉号”等基础数据。支持 Excel 批量导入/导出。
*   **硬件状态监控**：实时显示本地Agent连接状态、打印机在线状态。若断连或缺纸，页面顶部显示醒目的红色警告条。
*   **标签模板设置**：设置标签物理尺寸（宽/高 mm）、打印浓度、速度。提供“打印测试页”按钮用于校准纸张偏移。

## 五、 非功能需求

### 5.1 性能要求
*   **响应速度**：页面首屏加载时间 < 1.5秒；下拉搜索响应时间 < 0.5秒。
*   **打印延迟**：点击“开始打印”到打印机开始出纸的延迟 < 2秒（局域网内）。

### 5.2 兼容性与适配
*   **前端**：完美适配主流移动端浏览器（Chrome, Safari, 微信内置浏览器）及平板设备（iPad/安卓平板）。
*   **后端**：Docker 镜像需支持 `linux/amd64` 架构，确保在 Windows Docker Desktop 中流畅运行。

### 5.3 异常处理与弱网机制
*   **断网/断连处理**：若 WebSocket 断开，前端自动重连（3次），若失败则锁定“打印”按钮并提示“打印机离线”。
*   **防呆设计**：失效时间不能早于消毒时间；数量不能为0或负数；必填项未填时禁止提交并高亮提示。

## 六、 项目实施与交付计划

### 阶段一：原型设计与技术预研（第1周）
*   确定标签物理尺寸（如 40mm*30mm），输出高保真 UI 设计图。
*   在 Mac 环境下搭建 Node.js/Python 本地 Agent 原型，跑通“接收指令 -> 生成 PDF 预览”的 Mock 流程。

### 阶段二：Web端核心业务开发（第2-3周）
*   完成 Docker 内的前后端开发。
*   实现打印表单、数据字典管理、历史记录、统计报表等核心业务逻辑。
*   在 Mac 上通过 Mock 模式完成所有 UI 交互和业务逻辑测试。

### 阶段三：Agent开发与硬件联调（第4周）
*   完善 Windows 本地打印 Agent，接入真实的 Windows 打印 API。
*   在 Windows 10/11 宿主机上部署 Docker 和 Agent。
*   连接真实标签打印机，进行物理纸张的偏移量校准、浓度调试和连续打印压力测试。

### 阶段四：现场试运行与交付（第5周）
*   在口腔门诊实际环境中部署，消毒人员试用。
*   收集反馈，微调 UI 触控区域和语音播报音量。
*   编写《系统使用手册》与《打印机换纸/校准指南》，完成项目交付。
